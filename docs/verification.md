# Проверка стенда и лестницы — 11 сентября 2026

## Окружение

- macOS, JDK 25.0.2, Gradle Wrapper 9.3.1.
- Spring AI 2.0.1, Koog 1.2.0, Kotlin 2.3.10, kotlinx.serialization.
- Локальная Ollama, `qwen3:8b` (Q4_K_M). Для обоих фреймворков: temperature 0, контекст 16384, 2048 токенов на ответ, think=false.
- Данные настоящие: Docker Compose, HTTP, PostgreSQL. Заранее записанных улик нет.

Подтверждения в автоматических прогонах вводил тестовый скрипт. Это отдельные наблюдения, а не статистическое сравнение фреймворков.

## Что показали прогоны

- Шаг 0 на Spring и Koog дал дословно одинаковый ответ: одна модель, temperature 0, один промпт.
- Без стратегии `qwen3:8b` останавливается на симптоме и советует человеку проверку, которая доступна ей самой.
- Модель ставит ярлык, противоречащий собственному объяснению: в одном прогоне payment получил CONFIRMED с объяснением «зависимость в порядке». До причины довело правило кода «иди по зависимостям».
- В более раннем прогоне модель описала «запрос рестарта» только текстом, не вызвав tool. Поэтому под отчётом печатается журнал действий из кода, а не пересказ модели.
- Шаг 5 идёт разными путями: иногда сразу `terminateSession`, иногда рестарт payment с отказом человека. Оба исхода честные и оба показывают границу полномочий.

Подробные наблюдения по фреймворкам, включая три особенности Koog 1.2.0, — в [ladder.md](ladder.md).

## Ограничения, которые остаются

- Проверки кода отвечают за полноту трассы и границу действий, а не за правильность текста отчёта.
- Граф зависимостей код берёт из живого `/demo/status`, то есть правило «иди вниз по зависимостям» работает для этого стенда, а не вообще.
- Лимит вызовов tools, предел генерации на ответ и wall-clock deadline действуют на разных уровнях; суммарного бюджета токенов нет.
- Deadline запрещает новые вызовы tools и снимает ожидающие действия, но отмена уже начатой генерации зависит от клиента Ollama.
- Записи прогонов лежат в `captures/` и в git не попадают. Видео для сцены нужно записать отдельно.
