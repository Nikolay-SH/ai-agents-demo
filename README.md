# Sherlock: в 14:37 всё упало

Демо для парного доклада о Spring AI 2.0 и Koog. Один живой инцидент в Docker и шесть шагов: от голого вызова LLM
до агента с памятью, стратегией и подтверждением критичных действий человеком. Локальная модель в Ollama, MCP нет.

## Лестница

[Шаги, сценарий и тайминг доклада](docs/ladder.md).

```bash
./gradlew build installDist
./scripts/lab up
./scripts/lab fault lock
./scripts/demo spring step0   # … step5
./scripts/demo koog step0     # то же на Koog
```

Шаги 2–5 заканчиваются приглашением оператора: можно продолжить разговор репликой, пустой Enter завершает.
В шаге 5 агент запрашивает рестарт сервиса или завершение блокирующей сессии БД; консоль требует точную строку
`approve <id>`, а Enter, любой другой ответ, EOF и таймаут означают отказ. Tool подтверждения у модели нет.

## Что в проекте

- `demo-services` — checkout и payment: настоящие HTTP-вызовы, PostgreSQL и Hikari.
- `live-lab` — общие инструменты (Docker CLI, HTTP, JDBC, Prometheus), лимиты и барьеры подтверждения.
- `spring-agent`, `koog-agent` — две реализации лестницы на одних и тех же tools и промптах.
- `compose.yaml` — сервисы, нагрузка, Prometheus и Grafana (http://localhost:13000/d/sherlock-live).

## Требования

JDK 17+ (разработка и проверка — на JDK 25), Docker Compose, Ollama на localhost.
Первая сборка и загрузка образов требуют сети.

```bash
ollama list
# Только если сервер ещё не запущен:
ollama serve
# Только если этой модели нет:
ollama pull qwen3:8b
```

## Что гарантирует код, а не модель

- Лимиты: вызовы tools и активное время расследования. Время ответа человека в них не входит.
- Барьер действий: решение принимает человек в консоли, подтверждение одноразовое и привязано к конкретному
  контейнеру или сессии БД; если цель изменилась — действие отменяется.
- Журнал действий под отчётом печатает код: он покажет, что было выполнено на самом деле.
- Проверка улик: ссылки `[E#]` должны существовать, а подтверждённая причина — опираться на прямую проверку сервиса.

## Проверка

```bash
./gradlew test               # 17 тестов: бюджеты, консоль, барьеры рестарта и завершения сессии, HTTP/JDBC
python3 scripts/check-live.py  # барьер подтверждения на живом Docker, без LLM
./scripts/demo live status   # операторский harness: те же tools без агента
```
